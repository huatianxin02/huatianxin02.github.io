念起 nianqi

跨端个人记录应用 · macOS 原生 / Android / Web

Swift 5 / SwiftUI AppKit / Combine Carbon 全局热键 Java / WebView 原生 JavaScript IndexedDB 裸 swiftc 构建 aapt2 → apksigner

手机优先的「今日必做 + 随心记」双区记录工具。同一份数据契约覆盖三个端， 刻意不做账号、云同步、协作与提醒推送 —— 纯本地、零第三方依赖、零运行时权限。

设计理念

  • 按心理契约分区，不按功能分区：「今日必做」和「随心记」是两种心理契约， 是两个永不合并的独立区域 —— 有承诺的事给成就感（打卡、连续天数）， 无承诺的事给零压力（禁止任何统计）。把两者的统计混在一起，会同时破坏两边。
  • 绝不使用负面信号：13 项否决清单里最核心的一条。逾期不标红、不做红点与负面计数、 断签不清零（最长连续永久保留）、习惯只停用不删除。因为负面反馈是「做了反而更差」的功能 —— 压力会杀死打开欲。
  • 录入路径是唯一用秒数衡量的指标：从想到到记下 ≤ 3 秒。打开即聚焦光标、 顶部只有一个主输入框、Enter 即存、保存后保持聚焦可连续录入；明令禁止保存 toast、音效、 模态确认框与强制选择分类。唯一的反馈是新条目就地插入（≤180ms）。
  • 审美是一等功能需求，但必须可验收：字号只有 4 档、字重只有 2 档、 每套主题颜色 token ≤10、动效 120–200ms；8 个主题/模式组合的对比度全部要过 4.5:1， 触控命中区 ≥44×44。
  • 数据属于用户：导出是单文件全量 JSON（含墓碑记录）并带 schema 版本； 导入是合并而不是覆盖，只有本地侧有的必须保留；版本高于应用支持的 schema 直接拒绝， 绝不「尽力而为」地导入。
  • 把 macOS 客户端完整重写为纯 SwiftUI 原生应用：20 个 Swift 文件、4741 行， 无 Xcode 工程、无 SwiftPM、无第三方包，用裸 swiftc 构建出 2.5 MB 的 .app； 实现 ⌥Space 全局速记、菜单栏常驻、开机自启、运行时切换 Dock 图标， 并与 Web 版共用同一份 nianqi.json 数据文件，来回切换不丢数据。
  • 设计 --selftest 自检协议：把数据契约、8 组主题解析、 5 个图标变体的绘制像素、存档往返、合并语义、原生能力与渲染路径，全部变成可复跑的断言。
  • 定位并修复「自检自身失效」的隐蔽缺陷：初版用 ImageRenderer 渲染 ScrollView 只得到纯背景图，而「不透明像素」指标在铺满底色的视图上恒等于采样点数 76200， 空白图被判为正常。改走 NSHostingView + cacheDisplay 自渲染路径，度量换成 「颜色数 + 非背景像素占比」后，同一条视图从 1 种颜色恢复到 1027 种 / 内容占比 41.3%， 并新增渲染路径回归守卫。
  • 在 Google Maven 超时不可用的机器上绕过 Gradle / AGP，手工串起 aapt2 → javac → d8 → zipalign → apksigner 六步流水线，产出 50468 字节、 零运行时权限的 Android 16（targetSdk 36）应用，构建零网络依赖、可复现。
  • 靠模拟器端到端验证抓出 5 个缺陷并修复：Android 13+ 预测式返回改用 OnBackInvokedCallback；系统栏 insets 在页面就绪前派发导致的时序竞态； 分享内容被静默丢弃；勾选圆触控命中区从 24px 修正为 44px；墨主题说明文字对比度从 2.78:1 提亮到 4.51:1。
  • 建立三层 CDP 自动化验证，共 78 项断言（功能 37 / 视觉 22 / 端到端 19）， 并用 CDP 沿 DOM 逐层合成含 alpha 的背景色做 WCAG 对比度审计，驱动设计级修复， 正文对比度从 3.64 提升到 9.74。

02

心情笔记 MoodNotes

五端本地情绪日记 · macOS / Android / HarmonyOS / iOS / Web

Swift / Cocoa WKWebView 外壳 Java ArkTS（HarmonyOS NEXT） SwiftUI LocalAuthentication AVAudioRecorder hvigor / DevEco

完全本地的情绪日记，三种心情按颜色分类，支持文字、图片与录音。 架构是「一份共享网页界面 + N 个平台原生外壳」，各端桥协议保持一致， 网页代码在移植时一行未改。

设计理念

  • 情绪优先于文字：「不写字，也算记录」：只点一下心情、一个字都不写， 也算今天来过；允许无标题。因为真正的低潮期人是写不出字的 —— 如果记录一定要以「写一段话」为代价，它一定会在最需要它的日子断掉。
  • 日记真正的难点不是「写」，是「翻」：写的时候有情绪，翻的时候找不到。 于是做了历史上的今天、情绪对冲（今天难过就翻出过去开心的）、加权轮播回忆， 以及用「现在的自己」给旧笔记批注 —— 留言挂在原笔记上，不新建、也不改动原笔记的时间。
  • 数据是你的，不是我的：Android 清单里连 INTERNET 权限都没有， 无账号、无服务器。导出就是原件（完整备份 + 图片音频原文件），也能导出一篇一个 .md；每次保存前自动快照，解析失败时从最近可用快照自愈，损坏现场留成文件。
  • 界面要能退到背景里去：支持背景图片 / GIF / 10 秒内短视频； 从背景图自动提取 3 种主色并做对比度保护（太浅或太深都保证文字可读）， 静观模式下一段时间不操作，界面整体淡出、只留背景。
  • 刻意不做：云同步（数据主权 > 便利）、社交与排行榜（情绪不是拿来比较的）、 AI 代写日记（日记一旦是生成的，它就失去了全部意义）、「断签清零」式惩罚、广告与付费墙。
  • 用一套架构把同一产品铺到 5 个平台：网页层 5358 行 app.js + 1675 行 styles.css + 514 行 index.html；各端桥命令统一为 loadNotes / saveNotes / saveAsset / recStart / recStop / setReminder 等一组协议。
  • 建立 9 套、共 529 项自动化测试并全部通过 （mac2 / mac3 / feishu / mood / skin / picker / still / android / io）， 并把测试从 /tmp 迁入仓库内目录，避免被系统清理。
  • 从崩溃日志定位并根治 Android 端「一打开就闪退」： 日志为 PendingIntents attached to actions with remote inputs must be mutable， 链路是 onResume → refreshOngoingNote → showQuickNote → notify； 根因是带 RemoteInput 的 PendingIntent 在 API 31+ 必须为 FLAG_MUTABLE。按系统版本分流修复，并给全部通知调用加兜底 —— 发通知失败绝不能让 App 崩。
  • 把 macOS 外壳做成系统级应用：菜单栏图标按「今天记了没」显示实心/空心、 悬停显示连续天数、合盖唤醒跨天自动刷新、Touch ID 解锁、开机自启； 数据快照 + 损坏文件留证 + 自动挑选最新有效备份自愈 + 一键恢复，并支持 Markdown / PDF 导出。
  • Android 端全程纯离线：只申请录音、通知、开机自启、振动四项权限， 不含 INTERNET；数据落应用私有目录，开机自动重排每日与每周提醒。
  • 从零搭 HarmonyOS NEXT 的 ArkTS 桥：同步桥 + 启动时把网页资源拷进沙箱、 用 file:// 同源打开，使图片与音频可直接显示； 用 hvigor 编译出签名 HAP 492603 字节（期间因中文路径被构建检查拒绝，定位后改纯英文路径解决）。

余白 Yohaku · 墨間 Sumi

macOS 待办双形态 + Android 版 · 暖纸日间 / 夜色墨线

Swift 5 / SwiftUI XCTest MenuBarExtra SMAppService Java / WebView Canvas 2D xcodebuild CDP 三层验证

两款共用一套数据模型与设计语言的 macOS 原生应用 —— 余白是暖纸日间，墨間是夜色墨线 —— 再合并为一款 Android 应用。纯本机、无账号、无云同步。 昼夜切换不是换色，而是整套视觉语言的切换。

设计理念

  • 昼夜不是换个色，是换一整套视觉语言：纸面靠柔和投影表达卡片边界， 墨色靠 1px 细线（暗色投影会浮成灰块）；不用纯黑 —— 没有蓝调的黑久看眼睛发涩； 也不用纯白 —— 正文留一点和纸那样的微黄。连字重字距、插图画法与文案都随昼夜切换。 两面的主题色与背景各自独立持久化，白天挑的颜色不会被黑夜覆盖。
  • 颜色通道留给状态，不留给分类：主题色由用户自选（预设 + 取色器）， 所以任何写死的文字色都会在某个主题下失效。改为由代码按当前主题色动态派生两个 token： --accent-text（混到 ≥4.6:1，供文字用）与 --accent-contrast（叠在实底上的文字色）。 用户能改的颜色不能承载语义。
  • 语言也是设计：文案全部为中性陈述、不用感叹号、不喊口号 —— 「今天，慢慢来。」「今夜的事」「谢谢你，给今天留了一点时间。」 标题用细字重 + 宽字距表现安静，靠留白而不是装饰。
  • 坏数据先留证，绝不覆盖：先写临时文件并落盘再原子改名，保证不出现半个 JSON； 读取失败时返回哨兵值让界面层留证，而不是把坏数据覆盖掉。
  • 实现并逐字对齐两端一致的重复规则引擎：按天/周用天数差取模、 按月用月份差取模并夹取到 min(锚点日, 当月天数)， 使「每月 31 号」在 2 月正确落到 28 日；连续天数仅对「每天」习惯累加， 循环加安全上限兜底防死循环，并用 XCTest 覆盖重复规则与本机历史保存。
  • 把「一套结构、两种视觉语言」做进同一个应用：日间是纸面底色 + 投影卡片 + 填充式插图 + 字重 600 / 字距 −0.022em；夜间是炭黑底 + 1px 细线卡片无投影 + 纯线描插图 + 字重 300 / 字距 +0.075em。两面的主题色与背景各自独立持久化互不覆盖，连文案与品牌名都随昼夜切换。
  • 用代码按当前主题色动态派生对比度 token：不写死颜色，而是派生 --accent-text（往黑/白方向混到 ≥4.6:1，供文字用）与 --accent-contrast（实底上的文字色）， 使用户无论选哪个预设或用取色器自定义，正文都保证可读。
  • 把视觉质量变成可测量断言：横向溢出 0px、最小字号 ≥ 11px、 可点元素全部 ≥ 44px 高、日历格最小 62×44px、正文对比度 14.84:1（日间）/ 14.73:1（夜间）。
  • 建立三层自动化验证共 96 项断言（功能与规则 53 / 布局与可读性 28 / Android 端到端 15）。
  • Android 数据写入保证不留半个 JSON：先写临时文件并 fsync 落盘再 rename；读取失败时返回哨兵值，让网页层留证而不是覆盖坏数据。 构建与安装脚本也做了工程化：改名 → ad-hoc 重签 → 摘除开发构建 → 原子替换并保留最近 3 份归档。

汽车工艺文档智能问答助手

基于 RAG 的本地化文档问答系统 · AI 应用方向

Python RAG 检索增强生成 混合检索 · BM25 RRF 倒数排名融合 Qwen3-Embedding-4B Dify 1.17.1 RAGFlow DeepDoc Docker Compose LM Studio 本地推理

汽车电子的工艺文档表格密集、术语专业、版本迭代频繁 —— 工程师查一条锡炉温度标准值， 要在数十页 PDF 里翻出 17 处「锡炉」逐个核对；而直接问通用大模型，会得到一个 「看起来对、但没法用」的答案。我独立实现了三套 RAG 系统，让模型只依据企业自有文档作答， 每条答案都能回溯到原文位置，没有依据时主动拒答。

解析 · 章节/表格/页码→ 领域词典 + bigram→ hybrid 分块→ Qwen3-Embedding-4B→ numpy 向量库 + BM25→ RRF 融合召回→ 关键词重排→ 防幻觉提示词→ 带引用的答案
  • 从零实现自研 RAG 全链路（11 个模块、零外部服务依赖）：解析层用 pdfplumber 提取表格、并按字号与编号识别章节；分词层自建汽车电子术语词典（波峰焊、锡炉温度、三防漆、AQL、 GB/T 2828.1）配合 bigram；分块层用「章节感知 + 滑动窗口」的 hybrid 策略； 索引层是本地 numpy 持久化向量库 + BM25 倒排索引；检索层双路并行后用 RRF（k=60）融合； 溯源信息做到「章节 → 页码 → 片段类型」三级。
  • 关键决策：向量模型选型。沿用英文向量模型时，中文工艺查询的 Top1 命中率只有 60%，且相似度全部挤在 0.67–0.68 这个极窄区间 —— 这是典型的语义空间坍缩， 模型根本没能力区分这些中文文本。换成中文原生 Qwen3-Embedding-4B（2560 维）后， Top1 命中 60% → 100%、MRR 0.717 → 1.000。 结论：中文领域做 RAG，中文原生向量模型是及格线，不是优化项。
  • 定位并修复「答案为空但 token 拉满」：接口返回 completion_tokens 高达 1024+， 但答案内容为空，单题耗时 27–175 秒。根因是模型默认开启思考模式，推理过程占满全部输出配额， 轮到真正的答案时已无 token，而 OpenAI 兼容接口只读取正文内容字段。 在请求组装层强制注入关闭思考的参数后，同题耗时降到 3.8–9.1 秒、答案完整准确； 该开关在 9B 与 27B 两款模型上均验证有效，属跨模型通用开关（另外四种方案全部无效）。
  • 修复 PDF 表格文字污染正文导致的溯源错位：表格内容同时出现在正文流和表格对象中， 同一段文字被重复计入，导致表格编号整体错位一位 —— 这类 bug 不报错，只是页码全差一页。 改为按真实表标题归并表格行、并从正文中剔除已被表格捕获的文字后， 索引片段从 128 收敛到 104，溯源位置恢复准确。
  • 在内网受限环境下跑通平台化部署：Dify 1.17.1 全栈（15 个容器）通过 host.docker.internal 反向调用宿主机的本地模型服务，等价于生产环境的模型服务解耦； RAGFlow v0.20.3（5 个容器）跑通 DeepDoc 深度解析，输出的不是纯文本而是结构化 HTML 表格 （表标题被单独识别为 caption），每个片段还附带版面截图标识。 期间解决了镜像层反复 EOF 中断、插件市场 403 需自行离线打包、离线包签名校验、 轻量化模式不加载内置向量模型等问题（关键坑：离线包 ZIP 内不能包含目录条目）。
  • 建立 25 题评估集并做消融对比（20 道可答 + 5 道反幻觉拒答）： 纯向量检索 Hit@1 100% / 纯 BM25 94.7% / 混合检索 100%； 端到端关键词覆盖率 100%（25/25）、拒答正确率 100%（5/5）、幻觉率 0.0%、 平均延迟 4.39 秒。Dify 链路 7 题实测事实题 6/6、拒答 1/1、平均延迟 6.40 秒； RAGFlow 5 份 PDF 全部解析成功、共 39 个片段。

工程判断

  • 先做一遍再谈选型：如果一开始就直接挑平台用，很可能把「向量模型选错」 误判成「平台不行」。自己做一遍，才知道每个环节的正常表现该是什么样。
  • 报错信息经常指错方向：「输出为空但 token 拉满」看起来像接口协议问题， 实际是模型行为问题；「表格编号错位一位」看起来像分页 bug，实际是数据重复。 要顺着现象往下挖到机制层，而不是停在报错文字上。
  • 能测的都要测：幻觉率 0% 不是靠模型能力堆出来的，而是靠两道防线 —— 检索侧用混合检索加重排确保资料真的相关，生成侧用系统提示硬性约束 「只依据参考资料、缺失必须拒答、数值必须带单位与公差、句末方括号标注出处」。 那 5 道文档里根本没有答案的题，才是这个项目里最重要的设计。
  • 三选三，而不是三选一：自研 RAG、Dify 平台编排、RAGFlow DeepDoc 是按场景选型的能力储备，不是替代关系 —— 选型的本质是选代价。

能力边界（如实标注）

  • RAGFlow 的检索问答链路本轮未配置，这一轮聚焦验证的是 DeepDoc 文档解析能力。
  • 5 类工艺文档是按真实行业规范构造的仿真数据，不是企业真实资料。
  • 向量库是自研 numpy 实现、104 片段规模，未做生产规模验证； 生产环境需迁移到 FAISS / Milvus（索引接口已抽象，改动量小）。
  • 所用社区镜像实际是 amd64 构建，在 M1 上通过指令集转译运行 —— 解析速度的瓶颈归因于转译层，而非解析引擎本身。

贯穿它们的设计理念

一个设计理念的说服力，一半来自它拒绝做什么

「它追求的是我愿意每天打开它，
而不是帮我把事情清空。」

准则 01

按心理契约分区

「有承诺的事」需要成就感，「心血来潮记的事」需要零压力。两者混在一起会同时破坏两边，所以它们是永不合并的两个区域。

准则 02

绝不使用负面信号

不做逾期标红、红点与负面计数。逾期用琥珀色、断签不清零、习惯只归档不删除 —— 压力会杀死打开欲。

准则 03

3 秒录入

「从想到到记下」≤ 3 秒，这是唯一用秒数考核的指标。打开即聚焦、Enter 即存、保存静默成功。

准则 04

审美是一等功能，但必须可验收

字号只有 4 档、字重 2 档、颜色 token ≤10、动效 120–200ms；对比度 ≥4.5:1（8 组主题全过）、触控 ≥44px。

准则 05

颜色不承载语义

优先级只用 3/2/1 道竖条。主题色可由用户自选，因此文字色由代码动态派生，保证任何主题下都 ≥4.6:1。

准则 06

昼夜不是换色，是换整套语言

白天靠投影、夜里靠细线；不用纯黑也不用纯白。在「统一」的名义下抹平昼夜差异，等于丢掉两份设计的性格。

准则 07

数据属于用户

纯本地、零账号。导入是合并不是覆盖，平局按设备标识裁决，拒绝高版本 schema —— 同步做错比不同步更糟。

我刻意不做的事

  • 逾期标红 / 红色角标 / 任何负面计数 —— 典型「加了功能反而更差」
  • 断签的惩罚或提示 —— 断签是正常的，提示只会制造失败感
  • 保存时的 toast / 音效 / 模态确认框 —— 打断录入流
  • 强制选择分类 / 日期 / 优先级 —— 增加录入摩擦
  • 账号、登录、云同步 —— 数据主权 > 便利
  • 社交、点赞、排行榜 —— 情绪不是拿来比较的
  • AI 代写日记 —— 日记一旦是生成的，它就失去了全部意义
  • 首页弹窗 / 引导页 / 新手教程 —— 增加摩擦
  • 广告与付费墙
  • 「清空收件箱」—— 它追求积累，不追求清空
